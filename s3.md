# Amazon Simple Storage Service (S3)

## 1. Overview & Key Features

Amazon Simple Storage Service (Amazon S3) is an object storage service that offers industry-leading scalability, data availability, security, and performance. In addition to storing files and backups, S3 can directly host static websites (HTML, CSS, JavaScript, and images) without needing a traditional web server like Apache or Nginx.

**Key Features:**

* **Object Storage:** Store practically unlimited amounts of data as "objects" inside "buckets".
* **Static Website Hosting:** Serve static content directly to the internet with a dedicated HTTP endpoint.
* **High Durability:** Designed to provide 99.999999999% (11 9's) of data durability.
* **Granular Access Control:** Manage permissions using IAM policies, Bucket Policies, and Access Control Lists (ACLs).

## 2. Core Concepts

* **Bucket:** A container for objects stored in Amazon S3. Bucket names must be globally unique across all AWS accounts.
* **Object:** A file and any metadata that describes that file.
* **Static Website Endpoint:** A specific URL generated by AWS when you enable website hosting on a bucket (e.g., `http://<bucket-name>.s3-website-<region>.amazonaws.com`).
* **ACL (Access Control List):** A legacy, but still functional, way to manage access to individual objects (e.g., making specific files public).
* **Block Public Access:** A security feature activated by default that prevents public exposure of S3 data. It must be disabled to host a public website.

## 3. Hands-On Guide: Hosting a Static Website via CLI

### Task A: Create an S3 Bucket

You can create a bucket using the `s3api` command, which provides detailed control over the S3 APIs.

1. Ensure your AWS CLI is configured with the correct IAM credentials.
2. Run the create-bucket command specifying the region and a globally unique name:
```bash
aws s3api create-bucket --bucket <your-unique-bucket-name> --region us-west-2 --create-bucket-configuration LocationConstraint=us-west-2

```



### Task B: Adjust Bucket Permissions

By default, S3 blocks all public access to prevent accidental data leaks. To host a website, you must open these permissions.

1. In the **AWS Management Console**, navigate to the **S3 Dashboard** and select your bucket.
2. Go to the **Permissions** tab.
3. Under **Block public access (bucket settings)**, click Edit, uncheck **Block all public access**, and save.
4. Under **Object Ownership**, click Edit, select **ACLs enabled**, acknowledge the warning, and save.

### Task C: Enable Static Website Hosting

Tell S3 that this bucket should behave like a web server and specify the default landing page.

```bash
aws s3 website s3://<your-unique-bucket-name>/ --index-document index.html

```

*Note: You can verify this in the console under the **Properties** tab of your bucket, where the Endpoint URL will be displayed.*

### Task D: Upload Files (Copy vs. Sync)

You can upload your HTML/CSS files using the AWS CLI.

* **Using `cp` (Copy):** Uploads all files every time, regardless of whether they changed.
```bash
aws s3 cp /path/to/local/dir/ s3://<your-unique-bucket-name>/ --recursive --acl public-read

```


* **Using `sync` (Recommended):** Compares local files with the bucket and only uploads new or modified files, making deployments much faster and more efficient.
```bash
aws s3 sync /path/to/local/dir/ s3://<your-unique-bucket-name>/ --acl public-read

```



### Task E: Automate Deployments with a Bash Script

To make deployments repeatable, create an executable script (`update-website.sh`):

1. Open a text editor: `vi update-website.sh`
2. Add the deployment command:
```bash
#!/bin/bash
aws s3 sync /home/ec2-user/sysops-activity-files/static-website/ s3://<your-unique-bucket-name>/ --acl public-read

```


3. Make it executable: `chmod +x update-website.sh`
4. Run it whenever you update your local HTML/CSS files: `./update-website.sh`

## 4. Best Practices & Security

* **Use `aws s3 sync`:** Always prefer `sync` over `cp` when deploying websites or backing up directories to save bandwidth and time.
* **Bucket Policies over ACLs:** While this lab used ACLs (`--acl public-read`) for simplicity, AWS strongly recommends using **Bucket Policies** to grant public read access to the entire bucket seamlessly, leaving ACLs disabled.
* **HTTPS/SSL:** S3 Static Website Endpoints only support `HTTP`. For production websites requiring `HTTPS`, you must place an **Amazon CloudFront** distribution in front of your S3 bucket.
* **Least Privilege IAM:** The user executing the deployment scripts should only have `s3:PutObject` and `s3:ListBucket` permissions for that specific bucket, rather than full S3 administrator access.
